# Выкатка бэкенда

Бот и сервер подписок живут на `89.125.17.116` в `/opt/various-bot`.

## Зачем контейнеры

Сейчас оба сервиса крутятся под systemd в общем виртуальном окружении. Обновление
выглядит как «зайти по ssh, обновить код, перезапустить и надеяться»: окружение
меняется прямо на живом сервере, и если новая зависимость не встала — откатываться
не к чему.

С контейнерами откат — это предыдущий образ, и он уже собран.

## Первый переезд

Файлы этой папки нужно положить в `/opt/various-bot/deploy/`. `.env`, `various.db`
и `certs/` остаются на месте — они подключаются снаружи и в образ не попадают.

```
systemctl stop various-bot various-sub
bash deploy/deploy.sh
```

Старые юниты не удаляем сразу — пусть полежат выключенными неделю. Если что-то
пойдёт не так, вернуться можно одной командой:

```
docker compose -f deploy/docker-compose.yml down
systemctl start various-bot various-sub
```

Когда станет понятно, что всё работает:

```
systemctl disable various-bot various-sub
```

## Обновление

```
git pull
bash deploy/deploy.sh
```

Скрипт сперва делает копию базы, потом собирает образ и только затем
перезапускает. Порядок именно такой: при неудачной сборке ничего не падает —
бот продолжает работать на прежнем образе.

## Откат на предыдущую версию

Docker хранит прошлые образы. Посмотреть и вернуться:

```
docker images various-bot
```

```
docker tag various-bot:<нужный-id> various-bot:latest && docker compose -f deploy/docker-compose.yml up -d
```

## Что проверить после выкатки

Контейнер в списке «работает» ещё ничего не значит: падающий на старте бот
перезапускается по кругу и выглядит так же. Смотреть надо логи.

```
docker compose -f deploy/docker-compose.yml logs --tail=50 -f
```

И живой ответ сервера подписок:

```
curl -sk https://127.0.0.1:8088/healthz
```
